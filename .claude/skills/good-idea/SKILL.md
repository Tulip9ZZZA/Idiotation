# Good Idea

**A good idea is a bet with real structure, shaped to the specific gate it has to
pass, that gets stronger every time it passes.**

Everything else — elegance, surprise, compression, one-sentence frameworks — is
technique in service of that fit. This skill is the lens the whole kill-chain judges
through, so the pipeline measures against YOUR definition of good, not the models' taste.

## When to use

At every gate:

- **Gate 1 (Forge)** evaluates candidate theses against it.
- **Gate 2 (Kill)** tests its structure (can it be wrong? can we prove it wrong cheaply?).
- **Gate 3 (Roast)** tests its surface (does the structure show in a glance?).
- **Gate 4 (Lock)** confirms its loop (what compounds?).

If an idea fails the lens, it does not advance. Name the failed part. No hedging.

## The four-part test

### 1. Structure — it can be wrong

Name the load-bearing assumptions. If nothing can falsify it, it is not an idea — it is
a mood. "Just help people" fails: nobody is against it, so it carries no information.
A good idea stakes something: it makes a prediction that can lose.

- Ask: **What would make this wrong?**
- Then: what is the cheapest test that could actually falsify it?

### 2. Fit — it is shaped to a gate

Nothing works in the abstract. It works *for a gate*. The one-sentence novel hook is
not a law of storytelling — it is the shape of the shelf: a book is bought by a glance,
so the idea must be processable in a glance. Nvidia/AI is the other species: it doesn't
match one gate, it **lowers the cost of passing every gate**. Name which species the
idea is.

- Ask: **Who is the gate, and does this fit the shape of that gate?**
- Mirror failure modes: a universal multiplier too vague to act on (good idea, no
  buyer) vs a gate-matched pitch that only works for one gate (sells the book, nobody
  finishes it).

### 3. Surface — the structure shows

Can someone see the real thing in a glance and still find depth when they lean in?
The Mona Lisa's depth was *made* by technique: the depth is real AND it reads on the
surface. Surface only = a pitch. Structure only = invisible, and invisible ideas don't
work no matter how true they are. A good idea is one where **the real thing and the
sellable thing are the same thing**.

- Ask: **Can someone see it in a glance and still find the depth when they lean in?**

### 4. Loop — it compounds

What gets better the second time? The ladder is the wedge; the dataset is the moat.
Collect data, retrain, predict better, collect more. Without the loop you have a
novel — one-time sale, no compounding. With it, each pass makes the next pass cheaper.

- Ask: **What gets better the second time?**
- "No loop — accepted, one-time demo" is a legitimate answer ONLY if the gate is
  one-shot (a hackathon demo). Say it out loud; never pretend a loop exists.

## The relativity — the part people miss

Good idea is **relative to a gate, and gates open and close.** Leonardo was not a
worse artist in 1500 than in 1900 — patronage didn't buy depth; the museum/auction/
canon gate did. The idea didn't change; the filter did. Therefore:

- A good idea can be **early** — correct for a mechanism that does not exist yet.
- A good idea can be **dead** — correct for a mechanism that just closed.
- "Works" always means works-*somewhere-specific*.
- The one that looks like vision but is noise: **betting on a gate that doesn't exist
  and won't** — the difference from Leonardo is whether the gate is *coming* or
  *imagined*.

## Bad idea, seen from four angles

- **Unfalsifiable.** Can't lose, so it can't win. "We should solve climate change."
- **Gate-blind.** Real structure, wrong shape for the filter. Brilliant and unsellable.
- **Surface-only.** All pitch, no structure. The glance passes; nothing is behind it.
- **No loop.** Works once, then you start over. A demo, not a business.
- **Imaginary gate.** Betting on a filter that will never open.
- **Generic where specific was possible.** The most common failure in hackathons:
  saying what everyone is supposed to say, indistinguishable from saying nothing.

## Verdict scale

| Failed parts | Verdict |
|---|---|
| none | **GOOD** — advance |
| one | **NICE** — nod-worthy, not load-bearing; name the smallest change to pass |
| two | **BAD** — reshape or kill |
| three or more | **MOOD** — it was never an idea |

Do not hedge. Name the failed part and the smallest change that would pass.

## How to run

1. Take ONE idea (or thesis) and the gate name from `GATE_PROFILE.md`.
2. Work the four tests **in order** — structure first, because a thing with no
   structure needs no fitting.
3. For each part: verdict PASS/FAIL + one-line reason + the cheapest fix if FAIL.
4. Deliver the output contract. If comparing several ideas, run the contract once per
   idea and rank by number of failed parts, then by strength of structure.

## Output contract

```text
IDEA:
  one-line promise:
VERDICT: GOOD / NICE / BAD / MOOD
  failed parts:
GATE:
  name:
  state:
STRUCTURE:
  assumptions:
  falsification tests:
FIT:
  why this shape fits this gate:
  species: gate-matched / universal multiplier
SURFACE:
  visible in a glance:
  depth behind it:
LOOP:
  what compounds: [or "no loop — accepted, one-time demo"]
SMALLEST CHANGE TO PASS:
```

## Bad modes to refuse

Unfalsifiable · Gate-blind · Surface-only · No loop · Betting on a gate that will not
come · Generic where specific was possible · And the evaluator's own sin: hedging.
